# Product Quality

[← 디자인 계약으로 돌아가기](../../design.md)

정상 화면 밖의 상태, 접근성, 기기 대응, 콘텐츠 품질과 출시 검수 기준을 정의한다.

## System States

### Loading

- 첫 페이지 데이터가 500ms 이상 걸릴 가능성이 있으면 최종 레이아웃을 닮은 skeleton을 사용한다.
- 제출·복사·공유처럼 짧은 동작은 해당 버튼 안에서 진행을 표시한다.
- 기존 콘텐츠를 갱신할 때는 가능한 한 콘텐츠를 유지하고 진행 상태만 덧붙인다.
- 스크린 리더에 로딩 시작과 완료를 알린다.

### Recoverable Error

구성은 `무엇이 실패했는지 → 사용자가 할 수 있는 행동 → 대체 경로` 순서다.

- 질문 조회 실패: `질문을 불러오지 못했어요` + `다시 시도`
- 장소 조회 실패: `추천 장소를 불러오지 못했어요` + `다시 시도`
- 지도 실패: 장소 순서 목록 + `지도 다시 불러오기`
- 이미지 공유 실패: `이미지를 만들지 못했어요` + `다시 시도` + `닫기`

필드 오류는 해당 필드 바로 아래에 표시하고 입력값을 보존한다. 시스템 오류를 입력 필드 오류처럼 빨간 테두리로 표시하지 않는다.

### Empty

빈 화면은 짧은 제목, 이유 또는 의미, 하나의 다음 행동으로 구성한다.

- 기록 없음: `아직 남긴 여행 기록이 없어요` + `여행 시작하기`
- 진행 중 코스 없음: `진행 중인 코스가 없어요` + `장소 고르기`
- 팀원 없음: 실제로 가능한 상태인지 계약 확인 후, 가능하면 `아직 참여한 팀원이 없어요` + `초대하기`

### Permission Denied

- 권한 거부는 오류가 아니라 사용자의 선택으로 표현한다.
- 위치 공유 동의와 운영체제 위치 권한을 별개의 단계로 설명한다.
- 문구 예시: `위치 권한이 꺼져 있어 방문 인증을 사용할 수 없어요.`
- 가능한 경우 `설정 방법 보기`와 제한된 기능으로 계속하는 `나중에`를 제공한다.
- 같은 세션에서 거부 모달을 반복해서 자동 노출하지 않는다. `[F]`

### Offline and Timeout

- 오프라인에서는 마지막으로 확인한 코스와 장소 정보를 유지하고 실시간 위치·방문 인증이 중단되었음을 알린다. 캐시 가능 범위는 기술 검토 후 확정한다. `[B]`
- 요청 시간이 초과되면 무한 spinner 대신 재시도와 Home 경로를 제공한다.
- 재연결 성공 시 사용자가 별도 새로고침 없이 상태를 회복하도록 한다. `[F]`

### Success

- 등록, 장소 담기, 방문 인증, 공유 완료는 짧고 구체적으로 알린다.
- 성공 메시지는 다음 화면으로 이동하는 CTA를 가리지 않는다.
- 방문 인증 성공은 최소 1초 동안 체크와 `인증 완료`를 보여주되 모션 감소 설정을 존중한다.

## Accessibility

출시 기준은 WCAG 2.2 AA다.

- 일반 텍스트 대비 `4.5:1`, 큰 텍스트와 UI 경계 `3:1` 이상
- 프로젝트 내부 터치 목표 기준 `44×44px` 이상
- 모든 기능을 키보드로 사용할 수 있고 논리적 포커스 순서를 가짐
- 모든 포커스 가능한 요소에 보이는 포커스 링 제공
- 스와이프·드래그에는 탭 가능한 대체 수단 제공
- 색만으로 선택, 오류, 방문, 위치 상태를 전달하지 않음
- 모달은 포커스를 가두고 닫은 뒤 원래 트리거로 복원
- 장식 이미지는 빈 `alt`, 장소 사진은 장소명을 포함한 대체 텍스트 사용
- 200% 글자 확대에도 정보와 조작 손실 없음
- `prefers-reduced-motion`에서 자동 흔들림·펄스·스크롤 모션 중지
- 시간 제한이 있는 toast에만 중요한 정보를 두지 않음

## Responsive and Device Behavior

- 320px에서 가로 잘림 없이 동작한다.
- 360px, 390px, 430px에서 화면별 스냅샷을 검수한다.
- 세로 568px에서도 Primary CTA를 찾고 누를 수 있어야 한다.
- 가로 모드는 지도와 권한 안내가 겹치지 않는 최소 대응을 제공한다.
- 데스크톱은 모바일 프레임을 중앙 정렬하며 코스·지도만 전체 화면으로 늘리지 않는다.
- PWA standalone의 상태 표시줄, 홈 인디케이터, 키보드 높이를 고려한다.
- 화면 키보드가 입력과 오류 메시지, 제출 버튼을 동시에 가리지 않게 스크롤한다.

## Content and Tone

문체는 친근하지만 가볍게 희화화하지 않는다.

- 짧고 직접적인 해요체를 사용한다.
- 사용자를 탓하지 않는다: `잘못 입력했어요`보다 `식별코드를 확인해 주세요`.
- 추모·역사 장소에는 평가, 승패, 도장 깨기 표현을 사용하지 않는다.
- 시스템 용어(`COMMON200`, STOMP, 세션)를 사용자 문구에 노출하지 않는다.
- 오류는 상황과 해결 행동을 함께 쓴다.
- `TAB`처럼 의미가 불명확한 영문 행동 문구를 사용하지 않는다.
- 버튼은 명사보다 동사형 결과를 사용한다: `코스`보다 `코스 만들기`.

## Release Checklist

### Journey

- [ ] 모든 출시 대상 route가 placeholder가 아니다.
- [ ] 각 화면에 명확한 Primary 행동이 하나 있다.
- [ ] 모든 완료·빈 화면에서 다음 단계로 갈 수 있다.
- [ ] 신규·복귀·진행 중 사용자 분기가 합의된 계약과 일치한다.
- [ ] Back, Home, Menu의 결과가 화면마다 일관된다.

### Visual System

- [ ] 임의의 색·글자 크기·radius·그림자 값이 추가되지 않았다.
- [ ] 모든 CTA가 공용 버튼 규칙을 사용한다.
- [ ] 실제 장소 이미지와 missing-image fallback을 모두 검수했다.
- [ ] 기록 모드와 이동 모드가 같은 제품으로 보인다.

### States

- [ ] loading, empty, recoverable error, permission denied, offline을 확인했다.
- [ ] 네트워크 실패 후 사용자 입력과 선택이 보존된다.
- [ ] 중복 제출과 중복 방문 인증이 방지된다.
- [ ] 모달·시트의 열기, 닫기, Back 동작을 확인했다.

### Accessibility

- [ ] 색 대비 자동 검사와 수동 검사를 통과했다.
- [ ] 키보드만으로 전체 핵심 여정을 완료했다.
- [ ] VoiceOver 또는 NVDA로 주요 흐름을 확인했다.
- [ ] 모든 터치 목표가 내부 기준 44×44px 이상이다.
- [ ] 200% 글자 확대와 동작 줄이기 설정을 확인했다.
- [ ] 스와이프 기능을 버튼만으로 동일하게 수행할 수 있다.

### Devices

- [ ] 320×568, 360px, 390px, 430px 너비를 검수했다.
- [ ] iOS·Android의 safe area와 화면 키보드를 확인했다.
- [ ] PWA standalone과 일반 브라우저 모드를 모두 확인했다.
- [ ] 느린 네트워크와 지도 SDK 실패를 확인했다.
